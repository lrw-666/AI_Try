## 2. 本轮修正

1. **重写开关权限不符。**修正前 `--rewrite-extraction` 也能覆盖内容不同的既有文件；现在只重写相同内容，不同内容仍必须显式 `--force-overwrite`。本轮真实数据复核没有启用这些覆盖开关。
2. **固定 `.part` 名会覆盖合法文件。**原代码若遇到归档内同时有 `a.part` 和 `a`，后者可能把前者当临时文件截断并移走。改为同目录随机名称、独占创建临时文件，再原子替换；异常时只清理自己创建的临时文件。
3. **协议校验仅看总数。**原来的119正常+13异常也能通过总数132检查；现在命令行在读写前固定 `pcb1/seed42/120/12`，并核对按标签计数。库内通用划分函数仍可测试，但该命令不悄悄发布另一套协议。
4. **失败仍可能覆盖有效清单。**现在审计失败只写 `preparation-failure.json` 并退出，保留已有CSV及成功元数据；同名CSV内容不同也明确拒绝覆盖。成功输出使用原子发布，拒绝输出文件符号链接。
5. **教学与证据表述。**修正路径守卫解释；将“全部可读”收紧为“文件头可解析、尺寸可读”，完整像素解码仍留阶段04。正常/异常掩码原文件没有被改写。
6. **跨端换行符。**提交检查发现 Git 的自动CRLF转换可能改变清单和证据文件字节，导致另一台电脑校验SHA失败；新增仅针对本实验目录的 `.gitattributes`，保留原始字节，并核对暂存区内容与本机文件一致。

新增负向回归先复现了上述写入/协议问题，再验证修复；新增乱序输入不改变成员名单的回归。项目测试从16项增至23项。

## 4. 下一步：阶段04

继续使用当前环境，先读本验收记录、阶段索引及主指南，然后只做：

1. 加载启动入口，核对三份清单的SHA-256保持不变，不重新划分。
2. 对图像/异常掩码逐张完整解码，记录坏图、尺寸、模式、掩码原始取值和前景面积；正常图在内存中构造零掩码。
3. 在内存将原始非零缺陷ID合并为1，检查512等比例缩放与填充后的标签；掩码使用最近邻，填充255单独显示，不重写原始文件。
4. 输出固定训练集6正常+6异常、验证集3正常+3异常的原图、掩码、叠加图和512变换图，保存到资源目录的 `runs/data_preview`。
5. 审计精确重复和跨集近重复候选；相似度仅作为人工复核线索，不据此自动修改测试集或划分。
6. 创建 `04-data-audit-design-and-implementation.md`，说明实现、技术栈、结果、可视化位置及需要用户亲自确认的样例，更新阶段索引和README。
