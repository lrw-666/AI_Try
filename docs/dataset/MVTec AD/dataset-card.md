# 数据集卡：MVTec AD（原版二维数据集）

**核对日期：**2026-09-17  
**范围：**这里只讨论原版 MVTec Anomaly Detection，不包括 MVTec AD 2、MVTec 3D-AD 或 LOCO AD。  
**适合的起点：**在“只用正常样本训练”的条件下，学习图像级缺陷检测与像素级异常定位。  
**证据标记：**“论文／官网事实”指来源明确记载；“本地核对”指检查了当前项目中的文件；“研究判断／建议”指有待实验验证的分析。

**论文／官网事实：**缺陷包括划痕、凹陷、污染、形变、部件缺失及其他结构异常。研究者人工制作这些缺陷，以模拟真实检测问题；一张异常图可能包含不止一个标注区域。纹理类更侧重细微表面变化，物体类还涉及形状、结构和表面变化。[P19，§3、图 1–2]

**研究判断：**`metal_nut`、`screw`、`transistor`、`cable`、`pill`、`capsule` 可作为元器件／零部件检测的入门对象；纹理类适合练习底层图像处理。但名字相近不代表与导师将来提供的产品相同：材料、容许缺陷、镜头、背景和生产节拍都可能不同。先看原图与掩码，再选 2～3 类开展实验。

## 三、任务与标注：能训练、能评估什么？

- **图像级检测：**判断一张图是否至少有一处缺陷。连续异常分数可用于无需先定阈值的排序指标；真正的放行／拦截决策仍需确定阈值。
- **像素级定位／分割：**把异常热图或二值掩码与人工标注的缺陷区域比较。异常测试图提供 `ground_truth` 掩码；若评测纳入正常测试图，应将其真值视为全背景。
- **并非原生标注：**原版异常检测基准没有统一的缺陷框、逐像素缺陷*类型*、实例 ID、缺陷严重程度或返工成本标签。可以从掩码推导外接框，但那是新定义的任务／协议，不能直接冒称官方框检测结果。
- **训练前提：**官方 `train` 只含正常样本。某些方法使用 ImageNet 预训练主干，这属于额外外部训练数据，报告时必须说明。2019 与 2021 论文中的方法在预处理和训练需求上并不完全相同，不能把“只用 MVTec 正常图训练”理解成总数据使用条件完全一致。[P19，§4.1；P21，§6.1]

## 四、数据划分与泄漏：官方怎么分，哪里容易犯错？

**论文／官网事实：**每类有仅含正常图的 `train`，以及同时含正常图和异常图的 `test`；异常测试图的掩码单独存放。官网数据目录没有一个与训练／测试划分同等固定的统一验证集。2019 论文从正常训练图中随机留出一部分估计阈值，但未给所有方法统一的固定留出比例；2021 扩展基准明确把**每类原始正常训练图的 10%**随机留为验证集，并让比较方法共用该验证集。复现时不能混用两篇论文的协议。[P19，§3–4.3；P21，§6.1]

**主要泄漏风险：**

1. 不能看过官方测试缺陷掩码后据此挑模型、调阈值或后处理，再把相同测试集称为“未触碰的最终测试”。
2. 做切块、裁剪或数据增强时，先按**原始图像**划分，再生成派生样本；随机按小块划分会把近乎相同的内容分到训练与验证两侧。
3. 与论文对比时保留原类别和测试划分。若另做跨类别或少样本划分，保存文件清单、随机种子及原因，并明确称为“自定义协议”。
4. 仅用正常验证图可估计误报相关阈值，却无法直接测量真实漏检率。若用异常验证样本挑阈值，必须说明这已改变“无异常样本训练／调参”的前提。
5. 记录 ImageNet 等预训练权重、合成缺陷或其他工业数据集的使用；跨数据集训练可以研究，但必须符合所比较协议并透明报告。

**每次实验应保存：**数据版本与来源、类别、训练／验证／测试文件列表、随机种子、预处理、预训练来源、阈值确定方式，以及图像级／像素级评测是否纳入正常测试图。

## 五、成像条件：细小缺陷能否看清？

**论文／官网事实：**采集使用 2,048 × 2,048 工业 RGB 传感器、两种双侧远心镜头（放大倍率 1:5 和 1:1），随后裁剪图像。发布图像的边长因类别而异，约为 **700～1,024 像素**。`grid`、`screw`、`zipper` 仅提供单通道图像。光照总体受控，但部分类别有意改变光照；物体姿态和对齐程度也因类别而异。[P19，§3、表 1]

**研究判断：**过度缩小输入可能直接抹掉细缺陷。应记录原始尺寸、缩放比例、掩码面积和缺陷最小像素尺度；至少选择一个细微缺陷类别，比较整图与切块推理。对于灰度图，把单通道复制成三通道只是适配 RGB 预训练网络的实现方式，并不会增加颜色信息。

**不能据此推断：**在受控采集条件下表现好，不等于能应对新相机、失焦／光照漂移、生产节拍、设备磨损、批次变化或现场误报。MVTec AD 2 是另一套用于更复杂场景的数据集，不能与原版混为一谈。[官网；P19，§3]

## 六、评价指标：成绩能否反映漏检与误检？

| 要回答的问题 | 建议报告的指标 | 解读提醒 |
| --- | --- | --- |
| 能否把异常图排在正常图前面？ | 图像级 AUROC **和**图像级 AU-PR；逐类别及总体均值。 | 排序指标不负责选工作阈值，AU-PR 受异常占比影响。2019 论文表 2 则是在既定阈值下，分别报告正常图和异常图的正确分类比例。 |
| 能否找准缺陷像素？ | 像素级 AU-PR、像素级 AUROC，以及注明 FPR 积分上限的 AU-PRO。 | 2021 论文中测试像素只有约 **2.7%** 为异常，高像素 AUROC 仍可能伴随较差精确率。PRO 按缺陷区域考察重叠，避免只由大区域支配。[P21，§4] |
| 一个固定阈值能否用于检验？ | 在**验证集确定阈值**后，报告缺陷召回率／漏检率、误报率或每张正常图的误报数，以及 IoU、Dice 或逐区域重叠。 | 这是建议补充的工程指标，不是可互换的单个“官方成绩”。需给出混淆矩阵和阈值规则。 |
| 能否进入实际流程？ | 输入分辨率、延迟、峰值内存和失败案例图。 | 单个 AUROC 数字不能证明部署可行性。 |

**本地核对：**官方评估代码的 README 要求为**每张测试图**提供与原图同尺寸、取值连续的 `.tif`／`.tiff` 异常热图；代码计算图像分类 AUROC 和定位 AU-PRO，后者默认积分到 **FPR = 0.3**。公布结果时应同时保存评估代码版本和积分上限。2021 论文还报告像素级 AU-PR、AU-ROC、AU-PRO、AU-IoU；其中部分曲线面积限定了 FPR 范围。[P21，§4、表 3；本地评估代码 README]

**特别注意：**2019 论文“一个阈值下的逐区域重叠”不等于 2021 论文“AU-PRO 曲线面积”；“AU-PRO@0.3 = 0.924”也不等于“缺陷召回率为 92.4%”。不同协议、统计单位和分母的成绩不能直接比较。

## 八、开题价值：能验证什么，不能代表什么？

**可验证的问题：**只用正常图的异常检测与传统视觉规则相比如何；细缺陷和缩放带来什么损失；只用正常验证图怎样校准异常热图及阈值；AUROC、AU-PR、AU-PRO 为什么得出不同判断；C++／端侧推理速度与定位质量如何权衡。

**不能单独证明：**在陌生工厂产线可以直接部署、误剔与漏检的经济成本、跨相机／光照鲁棒性，或模型优于导师实际产品上的方案。这些结论需要目标场景样本、明确的检测规格，最好还要独立采集的评测数据。

**建议的首个可复现实验：**选一类纹理和一类相关零件；每类从正常训练图中留出 10% 作验证；各运行一个简单传统视觉基线和一个预训练特征异常检测基线；保存热图、掩码、误报／漏检案例、图像级 AUROC／AU-PR、像素级 AU-PR、AU-PRO@0.3 和推理耗时。先固定测试协议，再看测试失败案例作解释，避免反过来用测试集挑模型。
