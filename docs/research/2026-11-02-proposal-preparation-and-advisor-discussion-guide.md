### 2.3 PCB板级对象与单体器件不能混用

VisA PCB1—4属于含多个电子元件和复杂结构的板级图像，异常包括表面变化及缺失、错位等结构变化。“PCB外观缺陷”比“单体元器件表面划痕”更符合这批数据范围。[VisA官方说明](https://github.com/amazon-science/spot-diff)

带真实原图、GT和失败预测与导师讨论：输入为板级RGB外观图像，输出为可见缺陷像素；没有测量电气功能、内部缺陷、产线节拍或合格公差。

| 导师反馈 | 要作出的决定 | 当前成果怎样保留 |
| --- | --- | --- |
| 接受PCB板级外观对象 | 确定题目、缺陷定义和结论范围 | 直接作为前期基线，继续原整体路线 |
| 接受电子领域但需准确措辞 | 用样例解释表面与结构异常，修正背景 | 保留实现与协议，不改造成单体器件证据 |
| 必须研究单体器件 | 重新核数据、标注和监督划分，估变更成本 | PCB1仅作前期基础，不能只替换名词 |
| 必须仅用正常样本训练 | 明确监督条件改变，重定研究问题与协议 | 当前有监督结果不再是同协议答案 |

### 2.4 可改写的任务定义

> 本课题拟以公开VisA数据中的PCB板级RGB外观图像为对象，在有像素标注的监督条件下研究预训练视觉表征的缺陷二值分割迁移与适配。输入为图像，输出为对应原图的背景/缺陷掩码。已完成SegFormer-B0独立基线；后续拟建立冻结DINOv3-S/16与简单可训练分割头的独立对照，并根据失败证据选择一项适度适配，通过受控实验分析定位、正常误报与资源开销。最终对象与研究范围待导师确认，结论限定于实际数据和评价条件。

二值分割合并不同缺陷类型，不自动输出“划痕/缺失”等类别。领域上可说视觉检测，具体技术任务应写像素级分割。

## 4. 整篇论文拟研究什么

总问题：**在有限缺陷标注与消费级GPU条件下，怎样利用预训练视觉表征，兼顾PCB缺陷定位、正常区域误报与实现成本？**

### 4.1 研究问题与可检验假设

| 研究问题 | 拟检验假设，尚非结论 | 支撑或否定它需要什么 |
| --- | --- | --- |
| RQ1：两种迁移路线的效果/成本有何差异？ | 冻结DINOv3可能以较少可训练参数获得有价值的密集特征 | 同划分独立训练与评价，报告指标、训练参数、资源和失败 |
| RQ2：当前定位或误报瓶颈能否被适度适配缓解？ | 某一受控尺度/头部/监督调整可能改善对应错误 | train/val证据、明确改动、基线对照和必要消融 |
| RQ3：收益是否值得额外成本、适用范围在哪里？ | 指标收益可能伴随分辨率、计算或正常误报代价 | 同口径成本、正常FP、逐图分析；有条件再做补充验证 |

不预设DINO一定优于SegFormer，也不要求结果必须提升才能如实写研究。若无收益，应解释试验条件、负结果与边界；该研究是否满足学位深度仍须导师判断。

### 4.2 内容一：共同协议与SegFormer独立基线

当前实现已完成，后续需亲自掌握，并将协议写成可解释的前期基础。未来对照沿用原图清单、标签语义和指标数学定义；工程实现差异需要单独记录。

```text
PCB1固定原图清单与0/1掩码
  ├─ A：MiT-B0预训练＋新建二类头 → 全网络微调【已完成】
  └─ B：DINOv3-S/16预训练骨干冻结 → 简单分割头训练【开题后拟做】
      → 各自仅用train/val开发、定配置和选权重
      → 冻结协议评价：原图级global/macro、正常FP、成本、失败
      → 据train/val失败证据选一项适度适配 → 对照/消融 → 论文分析
```

这是两套独立方法的比较，不是默认的双编码器融合网络。预训练数据、目标、结构、规模和更新范围均不同，差异不能单独归因为“自监督胜过监督”或“某架构更好”。

### 4.3 内容二：冻结DINOv3-S/16＋简单分割头独立对照

这部分是开题后拟研究内容，不只是可删除的展望，也不要求在11月16日前完成训练。

1. **可获取性与环境：**按官方入口核个人账户访问条件和许可，固定权重/代码revision与SHA；没有权重时记录受阻，不能用随机骨干冒充预训练验证。
2. **几何与特征：**核输入归一化、尺寸/padding、patch tokens与原图位置关系；排除CLS/register tokens，再恢复空间网格，避免processor无意裁掉缺陷或打乱mask对应。
3. **冻结与头部：**骨干`requires_grad=False`、eval、无梯度提特征；简单头保留train与梯度。从逐位置线性映射/1×1卷积起步，其他小头另记配置。
4. **小规模可行性：**只用train/val做少量前向/反向与小子集检查，验证损失、梯度及实际参数变化；记录显存、主机内存、时间、可训练参数与输出尺度。
5. **完整训练与选模：**检查通过后制定预算，做正式train/val训练；保存配置、日志和best，按事先约定的val规则选择，不因test表现换方案。
6. **冻结后评价：**定下权重、预处理、阈值和后处理再评价，输出与SegFormer并列的结果、正常误报、逐图失败和成本；披露test先前已被看过。

官方资料见[DINOv3代码](https://github.com/facebookresearch/dinov3)、[模型卡](https://github.com/facebookresearch/dinov3/blob/main/MODEL_CARD.md)、[S/16入口](https://huggingface.co/facebook/dinov3-vits16-pretrain-lvd1689m)、[许可](https://github.com/facebookresearch/dinov3/blob/main/LICENSE.md)。据11月1日交接核查记录，权重访问需登录并同意相应条件；个人授权与本机加载尚未验证。后续执行时重新核实际入口，不在本文假装已经获得权限。

S/16的patch大小为16，512×512输入对应32×32空间网格；具体接口与额外token以实际模型为准。空间步长对细小缺陷构成风险，插值不能凭空恢复细节，但“小于16像素必然检测不了”也不是已证结论。

冻结减少梯度开销，不等于前向免费或必然比SegFormer快。先用本机RTX4070 Laptop约8GB实测，保留已验收SegFormer环境；若访问或资源受阻，先记录瓶颈、尝试有界配置，再与导师讨论替代/缩范围，不默认租云或改为大模型。目标是下游迁移，不重做大规模DINO预训练。

### 4.4 内容三：从失败证据选择一项适度适配

先完成两条独立路线的train/val比较，再选择一个主要问题；以下是候选菜单，不是同时必做清单。

| 有待确认的失败证据 | 可选的一项适配 | 最小必要比较 |
| --- | --- | --- |
| 尺度分析提示整图缩放后细节受损 | 受控输入分辨率或切块策略 | 同模型原方案/调整后；预定义尺度分组；资源与重组影响 |
| 冻结特征有信号而简单头定位不足 | 一处轻量解码头或选层调整 | 简单头/适配头，固定其他条件；必要组件消融 |
| 前景稀少与漏检/误报存在关联证据 | 一项有依据的损失或采样调整 | 固定数据、训练预算与阈值规则；定位与正常FP同时报告 |
| 两模型在train/val不同样本上互补 | 输出组合验证，或一处轻量融合/蒸馏 | 先比较两个单模型，再核新增信息与成本，不能只报组合成绩 |

选择时写清：**观察 → 假设 → 单一主要改动 → 对照/消融 → 指标与成本 → 失败或停止条件**。不一次改变分辨率、头、loss和阈值后把全部收益归给一个模块。普通切块、拼接或损失组合已有研究，不能直接称为首次提出。

特征融合、预测集成和蒸馏是不同设计；用DINO编码器配SegFormer风格头也不等于双编码器融合。只有互补证据、预算和导师优先级支持时才进入这一分支；否则围绕一条独立方案做适配即可。

## 5. 实验公平性与test接触边界

### 5.1 已有协议应讲清

- **划分/标签：**官方high-shot与派生v2分组train/val分开说明；正常全零，异常非零转1。letterbox生成255是忽略padding，不代表真实缺陷应被忽略。
- **迁移/损失：**MiT-B0编码器预训练，整个头新建，全网络微调；CE监督有效像素，前景Soft Dice只在有GT前景图逐图计算再平均，正常图仍由CE约束。
- **训练/选模：**反传、参数更新与纯推理不同；AMP跳步不等于成功更新。val IoU最高选best，并列取较早轮，test未参与选择best39。
- **还原/计分：**logits插值到512，裁padding、恢复原图，再softmax和阈值；GT用原始mask，不用缩小标签逆放大替代。
- **成本口径：**含PNG写盘的评价耗时不等于稳定单图推理延迟；现有显存只属于当前基线实测。

### 5.2 后续比较应预先约定

| 比较环节 | 应固定或记录的规则 |
| --- | --- |
| 数据与监督 | 两模型共用原图清单和0/1语义；先划分原图再增强/切块 |
| 模型特有处理 | 允许各自官方归一化；几何、输入尺寸和token处理逐项记录 |
| 调参与预算 | 各自可用train/val合理调参，预先约定尝试范围、训练/算力预算及选模规则 |
| 输出与指标 | 同原图GT、还原和数学定义；global、异常macro、正常FP并列 |
| 阈值与后处理 | 沿用0.5或仅用val选择的事先规则，冻结后再评价；不按test逐方法优化 |
| 适配与消融 | 固定其余条件，只检验主要改动；各组件取舍仍用train/val |
| 资源比较 | 同硬件、精度和计时范围，报告总/可训练参数、显存及实际时间；未测项明确标空 |
| 新协议或新配置 | 建新run、保存配置/来源/SHA，不覆盖当前验收基线和首次评价 |

公平不等于机械使用同一学习率；需使任务、评价与选择规则可比，并披露预训练来源、结构、规模和更新范围的混杂。若后续改变输入或评价协议而影响可比性，保留历史成绩，另做明确命名的可比运行；不能将新旧条件的数字直接归因为算法差异。

### 5.3 test已经看过，后续怎样做

首次test评价和固定协议技术复核已有留档；技术复核未重选epoch、改阈值、换权重或按成绩择优。现在test指标与失败图已被查看，不再称为从未接触的盲测。

后续DINO及适配仍只用train/val开发、选头、选超参数与阈值；冻结方案后才运行记录清楚的评价，并披露先前test接触及它对研究动机的影响。不能用这批test反复挑最好的新模型、失败后继续调再当成一次最终评价。

若要增强独立验证，可与导师讨论预先定义的额外类别或其他合适数据，按其协议保留测试部分；这是资源允许的补充，不能事后把已看过的PCB1重新命名为新盲测集。单seed、40张异常test图、未估计置信区间和无工业现场验证仍应如实写局限。

### 9.2 十二个常见追问

| 问题 | 回答边界 |
| --- | --- |
| 1. PCB和单体元器件是否相同？ | 板级RGB外观是当前数据对象，包含表面/结构异常；与单体器件不同，最终范围请导师确认。 |
| 2. 为什么做分割？ | 目标是缺陷像素定位，数据有mask；不自动识别缺陷类型或决定产品剔除。 |
| 3. 为什么选SegFormer和DINOv3？ | 前者为成熟独立分割基线，后者检验通用预训练冻结特征的迁移；需实测效果/成本，不预设后者更好。 |
| 4. 两条路线怎样训练？ | 当前MiT-B0编码器预训练、整个二类头新建且全网络微调；DINO拟冻结骨干只训练简单头，eval本身不能代替冻结。 |
| 5. “自监督DINO”是否不需要缺陷标签？ | 自监督描述其预训练；本课题用缺陷掩码训练分割头，下游仍为有监督分割。 |
| 6. 创新或贡献在哪里？ | 当前已有工程基线；拟通过独立对照与证据驱动适配形成实证/方法贡献，需文献、对照和消融验证，尚不能声称算法创新已成立。 |
| 7. 13步都做完了，后面做什么？ | 完成的是SegFormer工程闭环；DINO可行性、完整对照、一项适配及消融、综合分析和论文均未完成。 |
| 8. DINO开题前没结果可不可以？ | 当前安排不把它设为16日前置条件，以基线为前期基础，实质写清后续方案/风险；正式要求需导师确认，不能假报完成。 |
| 9. IoU0.6833算好吗，macro低是否说明小缺陷差？ | 是当前协议global前景IoU，同时报macro0.5249与正常FP；尚无模型对照，差值不单独证明尺度效应。 |
| 10. 为什么不直接融合，patch16会不会漏小缺陷？ | 融合要互补与预算证据，先独立对照；patch步长有定位风险，但不能断言小于16像素必漏，需受控验证。 |
| 11. test看过了，未来结果怎样可信？ | 透明披露首次评价/复核与已看失败图；未来开发选择仅用train/val，冻结后评价、保留独立run，不称完全盲测。 |
| 12. Agent辅助和论文工作量怎样说明？ | 如实说明辅助范围，亲自解释数据/梯度/评价及研究决策；按整体路线讨论最低必要研究内容与资源备选，不保证毕业或以测试数替代理解。 |

## 11. 开题后：整篇论文分阶段计划

下表按依赖组织，**各阶段实际起止日期须在学校中期、送审和毕业截止确认后倒排**。不把11月16日当作整篇论文完成日，也不在未知最终期限时承诺几周完成全部研究。

| 阶段 | 核心工作与工作量边界 | 阶段交付/进入下一步条件 |
| --- | --- | --- |
| M1：DINO独立可行性 | 核访问与版本、少量train/val、几何/token、冻结/梯度、显存/耗时；不直接长训练 | 可行性报告、真实资源与预算，或明确受阻和替代建议 |
| M2：DINO独立完整基线 | 检查通过后完整train/val训练、有限预算选配置/best，再冻结方案评价 | 与SegFormer并列的指标、逐图失败、正常FP、训练参数与成本表 |
| M3：证据驱动的一项适配 | 依据train/val选一个主要问题，实施一个主要改动与必要对照/消融 | 改动前后、组件必要性、收益代价、负结果与局限；不同时铺多条改进 |
| M4：补充验证，资源允许 | 按研究问题优先选多seed、另一PCB类别或支持性分析 | 重复性/适用范围证据；不作为自动全选清单 |
| M5：论文整合与定稿 | 前期章节可并行写；研究冻结后补结果、讨论、局限、送审/答辩材料 | 满足导师确认范围的论文，格式/引用/图表与证据一致 |

原路线的主体工作量是**一个已完成的SegFormer独立基线＋一个待实施DINO独立基线＋一项待证据选择的适配及必要验证**，还有协议、公平比较、错误/成本分析与写作。它是讨论稿，不是任意学校标准下的最低充分保证；具体最低项由导师与正式要求确定。

M1先用实测估计后续GPU时间、主动开发时间与存储成本，再锁M2预算。若受阻或预算不足，先削减M4与复杂融合分支；若主体仍不可行，带明确瓶颈与替代/缩范围方案讨论。不能因为开题前时间紧，就默默删掉开题后的DINO和适配。适配无提升也应如实分析，再与导师调整范围，不预承诺必须胜过基线。

## 12. 风险、取舍与定稿检查
